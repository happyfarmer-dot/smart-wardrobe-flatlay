# 5. 分階段 MVP 開發路線圖（Roadmap）與關鍵風險緩解檢查表

## 5.1 分階段 MVP 開發路線圖（Phased Roadmap）

| 階段 | 目標里程碑 | 核心交付項目 | 驗收指標 |
| --- | --- | --- | --- |
| **Phase 1 (Weeks 1–2)**<br/>端側視覺與數位入庫 MVP | 建立零雲端算力去背與一致化平拍體驗 | - React Web Canvas / Flutter 相機與相簿匯入<br/>- 去背 + Gray-World AWB + 25° 投影<br/>- K-Means++ 主色 HEX/HSL<br/>- FastAPI + PostgreSQL 入庫單次打標 | 單件衣物端側處理 `< 1.2s`，入庫僅呼叫一次 LLM，重複圖片 100% 雜湊去重 |
| **Phase 2 (Weeks 3–4)**<br/>身形校準與 2D 拼貼畫布 | 實現個人化比例縮放與平面層次視覺化 | - 全身照關鍵點比例量測 (`shoulder/torso/leg`)<br/>- 2D 多圖層 Z-Index 拖曳畫布<br/>- 一鍵 Tuck-in 紮衣服裁切遮罩<br/>- 選配頭部去背錨點 + PNG 匯出 | 畫布即時渲染 `60fps`，紮衣服遮罩邊界貼合褲頭線條 |
| **Phase 3 (Weeks 5–6)**<br/>混合穿搭推薦引擎 | 達成極低 Token 高精準度穿搭推薦 | - Stage-1 保暖、HSL 60-30-10、版型防呆過濾<br/>- SHA-256 推薦快取層 (`outfit_recommendations_cache`)<br/>- Stage-2 ID-Only Gemini 2.5 Flash + 離線 Fallback<br/>- 單品鎖定（一衣多穿）與風格切換 | 單次推薦雲端 Token `< 500`，快取命中率 `>= 40%`，無圖傳送 |
| **Phase 4 (Weeks 7–8)**<br/>生命週期、日曆與膠囊工具 | 提升長期留存與真實衣櫃使用率 | - OOTD 月曆排程 + 14 天防撞衫提醒<br/>- CPW 自動計算與 >90 天冷凍單品喚醒加權<br/>- 旅行膠囊最佳化求解器與打包清單 | 7 天旅遊僅需 `<= 8` 件核心單品即可達成 7 天不重複穿搭 |

## 5.2 關鍵風險緩解檢查表（Risk Mitigation Checklist）

| 風險類別 | 具體風險描述 | 緩解策略與工程防線 | 狀態 |
| --- | --- | --- | --- |
| **算力與成本風險** | 使用者批次匯入 100 件衣物或頻繁點擊「換一批」導致 LLM Token 暴增 | 1. 端側計算 `image_sha256` 阻止重複圖片打標<br/>2. Stage-1 規則引擎先濾除 >70% 不合適單品<br/>3. DB `outfit_recommendations_cache` 快取相同氣象與候選集<br/>4. 內建零 Token 本地語意 Fallback | 已實作 |
| **視覺割裂風險** | 自宅自然光、黃光與網購白底圖拼貼在一起產生強烈「剪貼簿違和感」 | 去背後強制在前景區域執行 Gray-World AWB + 限制增益邊界，並統一疊加 `25°` 柔和投影 | 已實作 |
| **去背邊緣偽影風險** | 白色襯衫在淺色牆面背景拍攝時發生前景被誤切（Over-segmentation） | 結合梯度邊緣偵測保護（Sobel/Luminance Gradient Guard），行動端優先採用語意分割遮罩（ML Kit / VisionKit），網頁端提供容差滑桿微調 | 已實作 |
| **推薦無解風險** | 過於嚴苛的 HSL 與保暖條件導致 Stage-1 候選集為空 | 設計分級放寬（Graceful Relaxation）：依序放寬「風格標籤」$\rightarrow$「色彩和諧門檻」$\rightarrow$「保暖誤差 ±1」，確保永遠能產出有效搭配 | 已實作 |
| **身形隱私外洩風險** | 使用者擔心全身照上傳雲端導致隱私疑慮 | 全身照僅在裝置端擷取 4 個比例數值（`shoulder/torso/leg`）存入資料庫，原始全身照**永不上傳伺服器** | 已設計 |
| **冷啟動流失風險** | 使用者一開始懶得拍 30 件衣服便放棄使用 | 支援多張相簿批次匯入、網購商品截圖直接裁切入庫，並提供 12 件膠囊基礎示範衣櫃可立即試用 | 已實作 |
